# 🎁 Вишлист на Новый год и дни рождения — Telegram Mini App

Кто-то создаёт компанию (семья, друзья, коллеги) со своей валютой — хоть во вьетнамских донгах — и зовёт людей по ссылке-приглашению. У компании есть повод: общий Новый год или дни рождения, где у каждого свой праздник. Внутри компании каждый собирает вишлист: подарки с ценой, фото, ссылкой на товар и комментарием («чёрная, размер M»), самые желанные можно отметить «⭐ Очень хочу». Если вставить ссылку на товар, название, цена и фото подтянутся сами. Потом выбирает друга и пишет, сколько готов на него потратить. Взносы складываются, и у каждого подарка видна шкала и сколько до него не хватает, а если хватает на всё — крупно «можно не скидываться». Кнопка «Чтобы хватило на …» подставляет ровно недостающую сумму. Кто сколько вложил, не видит никто. Участники сбора видят друг друга и могут завести общий чат в Telegram, чтобы договориться о покупке. Голосовать можно за несколько подарков: если денег хватает на два-три, в покупку попадут все, кто набрал больше голосов и помещается в бюджет. Кто-то из участников берёт покупку на себя («🛍 Я покупаю»): остальные видят, кому переводить, а после «✅ Куплено» сбор закрывается. А если хочется подарить что-то целиком самому, подарок можно забронировать («Подарю сам»): остальные увидят, что его кто-то дарит, но не узнают кто. Получил подарок — «🎉 Мне это подарили», и он уходит из сборов. Создатель компании может запустить Тайного Санту: бот случайно распределит пары и напишет каждому, кому он дарит. Бот сам сообщает о важном (новый участник, на подарок хватает, кто-то покупает, всё куплено) и напоминает о сборах за 14, 7, 3 и 1 день до Нового года.

Ботом можно делиться с кем угодно: вишлисты видят только участники одной компании.

Видео-демо: [`demo/wishlist-demo.mp4`](demo/wishlist-demo.mp4)

- **Фронтенд:** React 19 + Vite + Tailwind 4, статикой на GitHub Pages.
- **База:** Supabase (Postgres). Клиент вызывает только RPC-функции `public.wl_*`.
- **Авторизация** без паролей и Edge Functions: каждая RPC проверяет подпись Telegram `initData` (HMAC-SHA256 токеном бота) прямо в Postgres.

## Как устроено

```
Telegram ─► GitHub Pages (React) ── POST /rest/v1/rpc/wl_* + initData ──► Supabase
                                                                          │
                                         app.auth(): проверка подписи ◄───┘
                                         app.* таблицы (Data API их не видит)
```

- Таблицы лежат в схеме `app`, которую Supabase Data API не публикует. У ролей `anon` и `authenticated` нет к ним прав, а RLS включён на всякий случай.
- **Компании.** Подарки, взносы и голоса привязаны к членству в компании (`app.room_members`). Каждая RPC проверяет, что вы в этой компании, а выход из компании каскадом удаляет ваш вишлист, взносы и голоса в ней. Приглашение — ссылка `t.me/<бот>/<app>?startapp=r<код>`: по ней открывается экран «Вас пригласили» с кнопкой «Вступить».
- **Валюта** выбирается при создании компании (VND, RUB, USD, EUR, THB и др.; по умолчанию — по часовому поясу телефона) и потом не меняется. Суммы хранятся целыми числами (`bigint`, до 10¹²) — хватает и для донгов.
- **Приватность обеспечивает сервер, а не интерфейс.** RPC отдают по каждому подарку проценты, сколько до него не хватает (всего и без вашего вклада — для предпросмотра суммы), хватает ли, долю голосов, входит ли подарок в покупку. Чьих-либо взносов в ответах нет — свой видите только вы. Общая сумма сбора напрямую не показывается, хотя её можно вычислить как «цена − не хватает». Список участников сбора (с @username, чтобы написать в Telegram) и ссылку на их чат получают только сами участники этого сбора; остальные и владелец вишлиста их не видят. Кто за что голосовал, не видно никому. Владелец знает лишь, что ему кто-то скидывается.
- **Чат сбора.** Кнопка «Создать чат сбора» открывает системное окно Telegram «создать или выбрать чат» (`WebApp.requestChat`, Bot API 9.6+; на старых клиентах — ссылка `?startgroup=` «добавить бота в группу»). Бот становится администратором с правом приглашать, делает ссылку-приглашение с заявками и рассылает её участникам сбора в личку. Заявки он одобряет только участникам сбора. Добавить людей в чат сам бот не может — так устроен Telegram. Тем, кто присоединился к сбору позже, видна кнопка «Открыть чат сбора». Ссылку на свой чат можно вставить и вручную (`t.me/+…`, `t.me/joinchat/…`, `t.me/имя`), но тогда бот заявки не проверяет.
- **Бронь «подарю сам»** (`app.reservations`): один человек на подарок. Забронированный подарок выпадает из общего сбора — из процентов, «хватает на N из M» и голосования, а голоса, уже отданные за него, сбрасываются. Остальные участники получают только `reserved: true`, забронировавший — ещё `reserved_by_me`. Кто поставил бронь, API не отдаёт никому, а владелец вишлиста не видит даже факта брони. Бронь снимает только тот, кто её поставил. Она пропадает вместе с подарком и с выходом участника из компании.
- **Голосование с множественным выбором.** Участник сбора может голосовать за несколько подарков. Итоговый набор (`app.picked_gifts`) сервер собирает так: подарки по числу голосов (при равенстве — сначала дешевле) добавляются, пока хватает общего бюджета. Итог «покупаем …» появляется, когда проголосовали все участники сбора. Чтобы было видно, можно ли купить больше одного подарка, сервер считает и наборы: на сколько подарков хватает сразу (самые недорогие вместе — `together_missing` по нарастающей сумме цен), сколько не хватает ещё на один, и какие подарки влезут в придачу к выбранным по голосам (`extra_missing`). На экране это «Уже хватает сразу на 2 подарка из 4: книга + плед», «на любой из 2, но только на один» и у подарка «Хватит и вместе с выбранным». Если участник выходит из сбора, его голос пропадает. Если удалить подарок, пропадают и голоса за него, и его фото.
- **Повод компании** (`rooms.occasion`): `new_year` или `birthdays`. Выбирается при создании, потом его может сменить создатель компании. В новогодней компании шапка считает дни до Нового года и есть Тайный Санта. В компании дней рождения шапка показывает ближайший день рождения, участники отсортированы по дате, а Тайного Санты нет: при смене повода он скрывается и возвращается, если повод сменить обратно.
- **Дни рождения** (`users.birthday_month`, `users.birthday_day`): каждый указывает день и месяц, без года, одна дата на все компании. Видят её только участники компаний дней рождения. 29 февраля в невисокосный год празднуется 28-го. Бот за 14, 7, 3 и 1 день пишет остальным участникам компании: тем, кто в сборе, — договориться о покупке, остальным — заглянуть в вишлист. Имениннику с пустым вишлистом он напоминает за 14 и 7 дней, а в сам день поздравляет. Через неделю после дня рождения сбор закрывается сам (`app.close_birthday_pools`, если покупку ещё делают — ждёт до 30 дней): купленное сбором и забронированное отмечается подаренным, взносы, голоса, покупка и чат сбора удаляются, чтобы к следующему году всё началось с нуля. Сбор, начатый уже после дня рождения, не трогается.
- **Кто покупает** (`app.pool_purchases`): любой участник сбора жмёт «🛍 Я покупаю», когда по голосам выбран набор и на него хватает. Остальные участники видят покупателя и кнопку «Написать», не участники — только «подарок уже покупают». «✅ Куплено» закрывает сбор: взносы и голоса больше не меняются. «Отказаться» и «Вернуть сбор» доступны только самому покупателю.
- **«Мне это подарили»** (`received_at`): подарок остаётся в вишлисте отдельным разделом, но выпадает из сборов, голосов и броней.
- **Тайный Санта** (`app.santa`, `app.santa_members`): создатель компании открывает набор (можно с бюджетом) и сам сразу участвует, остальные жмут «Участвую». Жеребьёвка от трёх человек раскладывает всех по случайному кругу, поэтому никто не дарит сам себе. Каждый видит только своего получателя, бот присылает его и в личку.
- **Уведомления бота** (`app.notify`): сообщения пишутся в `app.notifications` и уходят через `pg_net` в Bot API. Telegram позволяет боту писать только тем, кто запускал его (/start) или разрешил это в приложении — остальным сообщения не дойдут. Напоминания рассылает `app.daily_reminders()` по расписанию `pg_cron` (каждый день в 03:00 UTC, часовой пояс отсчёта — `reminder_timezone` в `app.settings`).
- **Автозаполнение по ссылке**: Edge Function `telegram-bot` (действие `preview_link`) скачивает страницу товара как бот Telegram и достаёт из Open Graph, JSON-LD `Product` и `<title>` название, цену с валютой и картинку. Цена подставляется, только если валюта совпадает с валютой компании. Адреса localhost и частных сетей функция не открывает.
- Фото сжимаются на телефоне (до ~240 КБ, JPEG) и хранятся в `app.gift_images`. Списки и опрос шкал передают только версию фото (`image_rev`), а сами картинки клиент догружает пачкой и кэширует. База проверяет формат и сигнатуру файла (JPEG/PNG/WebP, без SVG).
- Шкалы обновляются у всех участников без перезагрузки: экран друга опрашивает базу раз в 4 секунды, пока открыт.

| RPC | Что делает |
| --- | --- |
| `wl_bootstrap` | мои компании, открытая компания, мой вишлист в ней, участники с процентами сборов |
| `wl_create_room` / `wl_room_preview` / `wl_join_room` / `wl_leave_room` | создать компанию (с поводом), посмотреть приглашение, вступить, выйти |
| `wl_set_room_occasion` | повод компании: Новый год или дни рождения — только создатель |
| `wl_set_birthday` | свой день рождения: день и месяц или убрать |
| `wl_save_gift` / `wl_delete_gift` | добавить, изменить, удалить свой подарок (с комментарием и «очень хочу») |
| `wl_set_gift_received` | «мне это подарили» или вернуть подарок в вишлист |
| `wl_set_gift_image` / `wl_gift_images` | прикрепить или убрать фото, получить фото (только из своих компаний) |
| `wl_friend` | вишлист друга: проценты по подаркам, мой вклад, доли голосов, итоговый набор; участникам сбора — ещё список участников и чат |
| `wl_set_pledge` | сколько я готов потратить (0 — выйти из сбора) |
| `wl_vote` | голос за подарок или его отмена; можно за несколько |
| `wl_set_pool_chat` | ссылка на Telegram-группу участников сбора |
| `wl_reserve_gift` | «подарю сам» — забронировать подарок или снять свою бронь |
| `wl_pool_purchase` | «я покупаю» / «отказаться» / «куплено» / «вернуть сбор» |
| `wl_santa` | Тайный Санта: открыть набор, участвовать, выйти, жеребьёвка, отмена |

## Развёртывание

### 1. Бот

1. В [@BotFather](https://t.me/BotFather) выполните `/newbot` и сохраните токен.
2. В `/mybots` → бот → *Bot Settings → Configure Mini App* включите Main Mini App с URL GitHub Pages (шаг 3), например `https://<user>.github.io/<repo>/`. Ссылки-приглашения тогда будут вида `t.me/<бот>?startapp=…`. Если вместо этого заводите приложение через `/newapp`, его short name задайте в переменной `APP_SHORT_NAME`.
3. Оформление: `/setuserpic` → [`branding/bot-avatar.png`](branding/bot-avatar.png) (крыса с подарком), `/setdescriptionpic` → [`branding/bot-description.png`](branding/bot-description.png). Исходник — [`branding/rat.svg`](branding/rat.svg), PNG пересобирает `node dev/make-branding.mjs`.

### 2. Supabase

1. Создайте проект и откройте **SQL Editor**.
2. Выполните [`supabase/migrations/20261020000000_wishlist.sql`](supabase/migrations/20261020000000_wishlist.sql). Если у вас Supabase CLI, можно `supabase db push`.
3. Сохраните токен бота. Без него база не сможет проверить подпись:

   ```sql
   insert into app.settings (key, value) values ('bot_token', '123456789:AA...')
   on conflict (key) do update set value = excluded.value;
   ```

   Срок жизни initData по умолчанию — сутки. Его меняет `('init_data_max_age', '<секунды>')`.

   Миграцию можно применять повторно: функции пересоздаются, данные остаются. Если вы успели поставить первую версию (без компаний), сначала удалите её тестовые данные: `drop schema app cascade;`.
4. В **Project Settings → API** возьмите Project URL и publishable key (`sb_publishable_…`; подойдёт и legacy anon key).

### 3. Бот: чат сбора, автозаполнение, уведомления (по желанию)

Edge Function нужна для кнопки «Создать чат сбора» и автозаполнения подарка по ссылке. Без неё всё остальное работает.

1. **Edge Function.** В Supabase откройте *Edge Functions → Deploy a new function → Via Editor*. Назовите функцию `telegram-bot`, вставьте код [`supabase/functions/telegram-bot/index.ts`](supabase/functions/telegram-bot/index.ts) и нажмите *Deploy*. В настройках функции выключите проверку JWT (*Verify JWT*): Telegram её не присылает. Подлинность запросов проверяется секретом вебхука, а запросы мини-приложения — подписью initData.
2. **Вебхук.** В SQL Editor выполните:

   ```sql
   select app.setup_telegram_webhook('https://<ref>.supabase.co/functions/v1/telegram-bot');
   -- через пару секунд проверьте: ждём {"ok":true,"result":true,...}
   select status_code, content::text from net._http_response order by id desc limit 1;
   ```

   Токен бота и секрет вебхука функция берёт из `app.settings`, отдельно их задавать не нужно.
3. **Уведомления и напоминания.** Миграция сама включает `pg_net` и `pg_cron`, если они доступны. Проверить можно в *Database → Extensions*; после включения вручную перезапустите миграцию. Расписание напоминаний: `select * from cron.job;`.

После обновления кода функции нажмите *Deploy* ещё раз — новая версия заменит старую.

### 4. GitHub Pages

1. Создайте репозиторий и запушьте проект в `main`.
2. В **Settings → Pages → Source** выберите **GitHub Actions**.
3. В **Settings → Secrets and variables → Actions → Variables** добавьте:

   | Переменная | Значение |
   | --- | --- |
   | `SUPABASE_URL` | `https://<ref>.supabase.co` |
   | `SUPABASE_KEY` | publishable key |
   | `BOT_USERNAME` | имя бота без `@` — **обязательно**, из него строится ссылка-приглашение |
   | `APP_SHORT_NAME` | short name из `/newapp`; без него ссылка ведёт на Main Mini App бота |

4. Workflow [`deploy.yml`](.github/workflows/deploy.yml) прогонит SQL-тесты, соберёт приложение и опубликует его. Publishable key — публичный ключ, ему место во фронтенде: доступ к данным всё равно даёт только валидная подпись Telegram.

Пригласить в компанию можно кнопкой «Пригласить в компанию» на вкладке «Участники» или из списка компаний — он открывается нажатием на название в шапке. Там же можно скопировать ссылку, переключиться на другую компанию, создать новую или выйти.

## Локальная разработка

```bash
npm install
npm run emulator
```

Команда поднимает настоящий Postgres в WASM ([PGlite](https://pglite.dev)) с той же миграцией и демо-данными (новогодняя компания «Друзья · Новый год» в донгах и «Работа» в рублях, где скидываются на дни рождения: у Ирины он через 5 дней), а также Vite. Эмулятор клиента Telegram откроется по адресу `http://127.0.0.1:5173/dev/emulator.html`. С параметром `?phones=1005:light:chat,1004:dark` левый телефон начинает с чата Telegram: кнопка «Пригласить» на правом присылает туда ссылку, а по ней открывается экран приглашения. Мини-приложение загружается в нём так же, как в web.telegram.org: initData передаётся в hash и подписывается тестовым токеном. Эмулятор рисует шапку, MainButton, кнопку «Назад» и системные алерты и отвечает на события `telegram-web-app.js`. Над каждым телефоном можно сменить пользователя и тему, а кнопка «Сбросить демо-данные» возвращает сид. Параметр `&fullscreen=1` включает полноэкранный режим Telegram, как на iOS: без шапки, с плавающими кнопками «Закрыть» и «⋯» и отступами safe area. Приложение учитывает их через `--tg-safe-area-inset-*` и `--tg-content-safe-area-inset-*`.

```bash
npm run test:sql      # тесты миграции и бота: подпись, права, сборы, голоса, фото, чат сбора, покупка, Санта, напоминания
npm run lint
npm run build
```

### Видео-демо

```bash
npx playwright install chromium   # один раз
npm run demo:record               # → demo/wishlist-demo.mp4 (нужен ffmpeg)
```

Сценарий лежит в [`dev/record-demo.mjs`](dev/record-demo.mjs). Катя зовёт Макса в компанию ссылкой в чате, он вступает и добавляет подарок по ссылке: название, цену и фото подставляет демо-магазин [`dev/demo-shop.mjs`](dev/demo-shop.mjs), так что интернет не нужен. Потом Макс одним тапом докидывает Алисе ровно столько, чтобы хватило сразу на три подарка. Катя и Макс голосуют за разные подарки, и в покупку попадают все три. Катя берёт покупку на себя и отмечает «Куплено», а в конце оба участвуют в жеребьёвке Тайного Санты. Демо-картинки подарков генерирует `node dev/make-demo-images.mjs`.

## Ограничения

- Шкалы и «не хватает N» обновляются в реальном времени, поэтому внимательный участник может заметить, на сколько вырос сбор после чьего-то взноса. Чужих взносов и имён рядом с ними интерфейс и API не показывают, но полную анонимность в маленькой компании не обеспечить.
- Автозаполнение работает не со всеми магазинами: часть из них отдаёт ботам пустую страницу или капчу. Тогда название и цену нужно ввести вручную.
- Валюту компании после создания не поменять: суммы не пересчитываются по курсу.
- Фото хранятся в базе, до 30 подарков у человека в компании и до ~300 КБ на фото. Для сотен активных пользователей лучше перенести их в Supabase Storage через Edge Function с той же проверкой initData.
