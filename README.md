# 🎁 Вишлист на Новый год — Telegram Mini App

Кто-то создаёт компанию (семья, друзья, коллеги) со своей валютой — хоть во вьетнамских донгах — и зовёт людей по ссылке-приглашению. Внутри компании каждый собирает вишлист: подарки с ценой, фото и ссылкой на товар. Потом выбирает друга и пишет, сколько готов на него потратить. Взносы складываются, и у каждого подарка видна шкала в процентах: на что уже хватает. Сколько собрано всего и кто сколько вложил, не видит никто. Участники сбора видят друг друга и могут завести общий чат в Telegram, чтобы договориться о покупке. Голосовать можно за несколько подарков: если денег хватает на два-три, в покупку попадут все, кто набрал больше голосов и помещается в бюджет. А если хочется подарить что-то целиком самому, подарок можно забронировать («Подарю сам»): остальные увидят, что его кто-то дарит, но не узнают кто.

Ботом можно делиться с кем угодно: вишлисты видят только участники одной компании.

Видео-демо: [`demo/wishlist-demo.mp4`](demo/wishlist-demo.mp4)

- **Фронтенд:** React 19 + Vite + Tailwind 4, статикой на GitHub Pages.
- **База:** Supabase (Postgres). Клиент вызывает только RPC-функции `public.wl_*`.
- **Авторизация** без паролей и Edge Functions: каждая RPC проверяет подпись Telegram `initData` (HMAC-SHA256 токеном бота) прямо в Postgres.

## Как устроено

```
Telegram ─► GitHub Pages (React) ── POST /rest/v1/rpc/wl_* + initData ──► Supabase
                                                                          │
                                         app.auth(): проверка подписи ◄───┘
                                         app.* таблицы (Data API их не видит)
```

- Таблицы лежат в схеме `app`, которую Supabase Data API не публикует. У ролей `anon` и `authenticated` нет к ним прав, а RLS включён на всякий случай.
- **Компании.** Подарки, взносы и голоса привязаны к членству в компании (`app.room_members`). Каждая RPC проверяет, что вы в этой компании, а выход из компании каскадом удаляет ваш вишлист, взносы и голоса в ней. Приглашение — ссылка `t.me/<бот>/<app>?startapp=r<код>`: по ней открывается экран «Вас пригласили» с кнопкой «Вступить».
- **Валюта** выбирается при создании компании (VND, RUB, USD, EUR, THB и др.; по умолчанию — по часовому поясу телефона) и потом не меняется. Суммы хранятся целыми числами (`bigint`, до 10¹²) — хватает и для донгов.
- **Приватность обеспечивает сервер, а не интерфейс.** RPC отдают по каждому подарку только проценты: собрано всего и без вашего вклада (для предпросмотра суммы), хватает ли, долю голосов, входит ли подарок в покупку. Сумм в ответах нет никогда — свою видите только вы. Список участников сбора (с @username, чтобы написать в Telegram) и ссылку на их чат получают только сами участники этого сбора; остальные и владелец вишлиста их не видят. Кто за что голосовал, не видно никому. Владелец знает лишь, что ему кто-то скидывается.
- **Чат сбора.** Бот не может создать группу сам, поэтому её создаёт кто-то из участников и вставляет ссылку-приглашение (`app.pool_chats`, только `t.me/+…`, `t.me/joinchat/…` или `t.me/имя`). Кнопку «Открыть чат сбора» видят только участники этого сбора.
- **Бронь «подарю сам»** (`app.reservations`): один человек на подарок. Забронированный подарок выпадает из общего сбора — из процентов, «хватает на N из M» и голосования, а голоса, уже отданные за него, сбрасываются. Остальные участники получают только `reserved: true`, забронировавший — ещё `reserved_by_me`. Кто поставил бронь, API не отдаёт никому, а владелец вишлиста не видит даже факта брони. Бронь снимает только тот, кто её поставил. Она пропадает вместе с подарком и с выходом участника из компании.
- **Голосование с множественным выбором.** Участник сбора может голосовать за несколько подарков. Итоговый набор (`app.picked_gifts`) сервер собирает так: подарки по числу голосов (при равенстве — сначала дешевле) добавляются, пока хватает общего бюджета. Итог «покупаем …» появляется, когда проголосовали все участники сбора. Если участник выходит из сбора, его голос пропадает. Если удалить подарок, пропадают и голоса за него, и его фото.
- Фото сжимаются на телефоне (до ~240 КБ, JPEG) и хранятся в `app.gift_images`. Списки и опрос шкал передают только версию фото (`image_rev`), а сами картинки клиент догружает пачкой и кэширует. База проверяет формат и сигнатуру файла (JPEG/PNG/WebP, без SVG).
- Шкалы обновляются у всех участников без перезагрузки: экран друга опрашивает базу раз в 4 секунды, пока открыт.

| RPC | Что делает |
| --- | --- |
| `wl_bootstrap` | мои компании, открытая компания, мой вишлист в ней, участники с процентами сборов |
| `wl_create_room` / `wl_room_preview` / `wl_join_room` / `wl_leave_room` | создать компанию, посмотреть приглашение, вступить, выйти |
| `wl_save_gift` / `wl_delete_gift` | добавить, изменить, удалить свой подарок |
| `wl_set_gift_image` / `wl_gift_images` | прикрепить или убрать фото, получить фото (только из своих компаний) |
| `wl_friend` | вишлист друга: проценты по подаркам, мой вклад, доли голосов, итоговый набор; участникам сбора — ещё список участников и чат |
| `wl_set_pledge` | сколько я готов потратить (0 — выйти из сбора) |
| `wl_vote` | голос за подарок или его отмена; можно за несколько |
| `wl_set_pool_chat` | ссылка на Telegram-группу участников сбора |
| `wl_reserve_gift` | «подарю сам» — забронировать подарок или снять свою бронь |

## Развёртывание

### 1. Бот

1. В [@BotFather](https://t.me/BotFather) выполните `/newbot` и сохраните токен.
2. В `/mybots` → бот → *Bot Settings → Configure Mini App* включите Main Mini App с URL GitHub Pages (шаг 3), например `https://<user>.github.io/<repo>/`. Ссылки-приглашения тогда будут вида `t.me/<бот>?startapp=…`. Если вместо этого заводите приложение через `/newapp`, его short name задайте в переменной `APP_SHORT_NAME`.
3. Оформление: `/setuserpic` → [`branding/bot-avatar.png`](branding/bot-avatar.png) (крыса с подарком), `/setdescriptionpic` → [`branding/bot-description.png`](branding/bot-description.png). Исходник — [`branding/rat.svg`](branding/rat.svg), PNG пересобирает `node dev/make-branding.mjs`.

### 2. Supabase

1. Создайте проект и откройте **SQL Editor**.
2. Выполните [`supabase/migrations/20261020000000_wishlist.sql`](supabase/migrations/20261020000000_wishlist.sql). Если у вас Supabase CLI, можно `supabase db push`.
3. Сохраните токен бота. Без него база не сможет проверить подпись:

   ```sql
   insert into app.settings (key, value) values ('bot_token', '123456789:AA...')
   on conflict (key) do update set value = excluded.value;
   ```

   Срок жизни initData по умолчанию — сутки. Его меняет `('init_data_max_age', '<секунды>')`.

   Миграцию можно применять повторно: функции пересоздаются, данные остаются. Если вы успели поставить первую версию (без компаний), сначала удалите её тестовые данные: `drop schema app cascade;`.
4. В **Project Settings → API** возьмите Project URL и publishable key (`sb_publishable_…`; подойдёт и legacy anon key).

### 3. GitHub Pages

1. Создайте репозиторий и запушьте проект в `main`.
2. В **Settings → Pages → Source** выберите **GitHub Actions**.
3. В **Settings → Secrets and variables → Actions → Variables** добавьте:

   | Переменная | Значение |
   | --- | --- |
   | `SUPABASE_URL` | `https://<ref>.supabase.co` |
   | `SUPABASE_KEY` | publishable key |
   | `BOT_USERNAME` | имя бота без `@` — **обязательно**, из него строится ссылка-приглашение |
   | `APP_SHORT_NAME` | short name из `/newapp`; без него ссылка ведёт на Main Mini App бота |

4. Workflow [`deploy.yml`](.github/workflows/deploy.yml) прогонит SQL-тесты, соберёт приложение и опубликует его. Publishable key — публичный ключ, ему место во фронтенде: доступ к данным всё равно даёт только валидная подпись Telegram.

Пригласить в компанию можно кнопкой «Пригласить в компанию» на вкладке «Участники» или из списка компаний — он открывается нажатием на название в шапке. Там же можно скопировать ссылку, переключиться на другую компанию, создать новую или выйти.

## Локальная разработка

```bash
npm install
npm run emulator
```

Команда поднимает настоящий Postgres в WASM ([PGlite](https://pglite.dev)) с той же миграцией и демо-данными (компания «Друзья · Новый год» в донгах и «Работа» в рублях), а также Vite. Эмулятор клиента Telegram откроется по адресу `http://127.0.0.1:5173/dev/emulator.html`. С параметром `?phones=1005:light:chat,1004:dark` левый телефон начинает с чата Telegram: кнопка «Пригласить» на правом присылает туда ссылку, а по ней открывается экран приглашения. Мини-приложение загружается в нём так же, как в web.telegram.org: initData передаётся в hash и подписывается тестовым токеном. Эмулятор рисует шапку, MainButton, кнопку «Назад» и системные алерты и отвечает на события `telegram-web-app.js`. Над каждым телефоном можно сменить пользователя и тему, а кнопка «Сбросить демо-данные» возвращает сид. Параметр `&fullscreen=1` включает полноэкранный режим Telegram, как на iOS: без шапки, с плавающими кнопками «Закрыть» и «⋯» и отступами safe area. Приложение учитывает их через `--tg-safe-area-inset-*` и `--tg-content-safe-area-inset-*`.

```bash
npm run test:sql      # тесты миграции: подпись, права, сборы, голоса, фото
npm run lint
npm run build
```

### Видео-демо

```bash
npx playwright install chromium   # один раз
npm run demo:record               # → demo/wishlist-demo.mp4 (нужен ffmpeg)
```

Сценарий лежит в [`dev/record-demo.mjs`](dev/record-demo.mjs). Катя зовёт Макса в компанию ссылкой в чате, он вступает, собирает вишлист в донгах и скидывается Алисе. Катя бронирует книгу, чтобы подарить её сама, затем оба голосуют. Демо-картинки подарков генерирует `node dev/make-demo-images.mjs`.

## Ограничения

- Проценты обновляются в реальном времени, поэтому внимательный участник может заметить, на сколько вырос сбор после чьего-то взноса. Сумм и имён интерфейс и API не показывают, но полную анонимность в маленькой компании не обеспечить.
- Валюту компании после создания не поменять: суммы не пересчитываются по курсу.
- Фото хранятся в базе, до 30 подарков у человека в компании и до ~300 КБ на фото. Для сотен активных пользователей лучше перенести их в Supabase Storage через Edge Function с той же проверкой initData.
